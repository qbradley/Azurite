CRITICAL ISSUE #2: blockErrorRequest Logic Bug
───────────────────────────────────────────────
FILE: rust/crates/azurite-blob/src/middlewares/preflight_middleware_factory.rs
LOCATION: apply_cors_request() lines 235-237

BUGGY CODE:
  if blockErrorRequest && err.is_none() {
      return None;  // ← WRONG: Drops None error! Should pass through
  }

ANALYSIS:
The condition is backwards. When blockErrorRequest=true and err.is_none():
- We return None (effectively dropping/consuming the error)
- This means if first CORS middleware succeeds with no error...
- The error state becomes None
- Second CORS middleware at line 234 never runs (condition checks pending_error.is_none())

EVIDENCE FROM blob_request_listener_factory.rs:
  Line 234: if pending_error.is_none() {
                pending_error = self.corsRequestMiddleware.apply(None, ...)
  
This second middleware only runs if no error exists from first one!

COMPARE TO TYPESCRIPT (BlobRequestListenerFactory.ts):
  app.use(preflightMiddlewareFactory.createCorsRequestMiddleware(
      this.metadataStore,
      true   ← blockErrorRequest=true
  ));
  app.use(preflightMiddlewareFactory.createCorsRequestMiddleware(
      this.metadataStore,
      false  ← blockErrorRequest=false
  ));

Both run ALWAYS, independently. TypeScript doesn't have this conditional logic.

FIX: 
Option A - Remove the check entirely:
  if blockErrorRequest && err.is_none() {
      return None;
  }
  Should be deleted - always return err

Option B - Fix the logic:
  The pattern seems to want: first pass handles errors, second handles success
  But implement correctly in blob_request_listener_factory.rs instead
