ROOT CAUSE ANALYSIS:
────────────────────

PROBLEM #1: Middleware Execution Order
Location: blob_request_listener_factory.rs lines 222-264

The issue:
  ① corsErrorRequestMiddleware at line 222-232
  ② corsRequestMiddleware at line 234-244
  ③ serializer_middleware at line 246-252
  ④ optionsHandlerMiddleware at line 254-264

Should be:
  ① corsErrorRequestMiddleware
  ② corsRequestMiddleware
  ③ optionsHandlerMiddleware ← MUST be before serializer
  ④ serializer_middleware

Why it matters:
  - Serializer converts response objects to wire format
  - After serialization, response is locked (can't change status codes, add headers)
  - OPTIONS handler needs to run BEFORE serialization to set headers/status
  - Currently tries to set headers AFTER serialization (too late)


PROBLEM #2: blockErrorRequest Logic
Location: preflight_middleware_factory.rs lines 235-237

The condition:
  if blockErrorRequest && err.is_none() {
      return None;  // Drops error
  }

Is wrong because:
  - blockErrorRequest=true means "only handle errors"
  - err.is_none() means "no error"
  - So condition is: if (only_handle_errors) AND (no_error) → drop it
  - This drops the error for successful requests!
  - Breaks the error chain

Used in blob_request_listener_factory.rs:
  Line 234: if pending_error.is_none() {
                corsRequestMiddleware.apply(...)

  If first middleware (blockErrorRequest=true) returns None due to the bug:
  - pending_error becomes None
  - Line 234 executes second middleware
  - But second middleware might also be affected by same bug

The fix:
  - Remove the check entirely
  - Let both middleware instances run
  - Each handles their own logic based on method and error state
