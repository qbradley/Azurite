PHASE 6: ERRORS & CONTEXT (5 modules, ~1,000 lines Rust)
   6.1 StorageError (110 lines)
       - Base error class extending MiddlewareError
       - XML body generation with proper escaping
       - Header injection (x-ms-error-code, x-ms-request-id)
       - Timestamp generation at construction (RFC3339 millis, UTC)
       Status: ✅ COMPLETE

   6.2 StorageErrorFactory (680 lines)
       - 74 static factory methods for blob errors
       - Error family groups: existence, validation, auth, lease, copy, etc.
       - Proper status codes, messages, and XML elements
       - Quirks preserved: getInvalidTag returns "DuplicateTagNames"
       Status: ✅ COMPLETE (largest single file)

   6.3 NotImplementedError + NotImplementedinSQLError (50 lines)
       - Helper functions returning 501 APINotImplemented errors
       - Two variants: generic and SQL-scoped messages
       Status: ✅ COMPLETE

   6.4 StrictModelNotSupportedError (40 lines)
       - Returns 500 FeatureNotSupported error
       - Interpolates feature name with --loose guidance
       Status: ✅ COMPLETE

   6.5 BlobStorageContext (137 lines)
       - Wrapper around generated Context
       - Blob-specific accessors: account, container, blob, loose, etc.
       - Interior mutability for getters/setters
       - xMsRequestID alias for contextId
       Status: ✅ COMPLETE

PHASE 7: AUTHENTICATION (9 modules + permission tables, ~1,300 lines Rust)
   7.1 IAuthenticator (14 lines)
       - Trait with async validate method
       - Tri-state return: Some(true), Some(false), None
       Status: ✅ COMPLETE

   7.3 IBlobSASSignatureValues (479 lines)
       - Struct with 24 fields (version through delegatedUserTenantId)
       - 8 generator functions:
         * 4 service SAS generators (2015-04-05, 2018-11-09, 2020-12-06, 2015-04-05)
         * 4 UDK generators (2018-11-09, 2020-02-10, 2020-12-06, 2025-07-05)
       - Canonical name building (no URL encoding)
       - Version dispatch via string comparison
       Status: ✅ COMPLETE

   7.4 BlobSASPermissions (54 lines)
       - Enum: Read, Add, Create, Write, Delete, DeleteVersion, Tag, Move, execute, SetImmutabilityPolicy, permanentDelete
       - Casing quirk preserved: execute and permanentDelete lowercase
       Status: ✅ COMPLETE

   7.5 BlobSASResourceType (29 lines)
       - Enum: Container, Blob, BlobSnapshot
       - Snapshot is two-character code "bs"
       Status: ✅ COMPLETE

   7.6 ContainerSASPermissions (44 lines)
       - Enum: Read, Add, Create, Write, Delete, List, Filter, Any
       - Any/"AnyPermission" is sentinel, not a permission character
       Status: ✅ COMPLETE

   7.8 OperationAccountSASPermission (121 lines)
       - Account SAS permission table (one entry per blob operation)
       - Validation methods: validateServices, validateResourceTypes, validatePermissions
       - ANY-character matching semantics
       Status: ✅ COMPLETE

   7.9 OperationBlobSASPermission (162 lines)
       - Two permission tables: BLOB_PERMISSIONS, CONTAINER_PERMISSIONS
       - One entry per operation
       - ANY-character matching, sentinel handling
       - Snapshot routes through CONTAINER table
       Status: ✅ COMPLETE

   7.10 BlobSharedKeyAuthenticator (277 lines)
        - Implements IAuthenticator
        - String-to-sign: method\n + headers\n + x-ms-headers\n + resource
        - Content-Length: 0 special case (returns "")
        - Key1 and key2 fallback
        - Secondary endpoint "-secondary" suffix support
        Status: ✅ COMPLETE

   7.11 AccountSASAuthenticator (276 lines)
        - Implements IAuthenticator
        - Requires: sv, se, sp, ss, srt, sig
        - Strict mode rejects ses with StrictModelNotSupportedError
        - Signature validation before other checks
        - Existing blob Write requirement for create/copy
        - IP and protocol validation stubs (always pass)
        Status: ✅ COMPLETE

   7.12 BlobSASAuthenticator (449 lines)
        - Implements IAuthenticator
        - Service SAS path: signature against key1/key2
        - UDK path: 6 signed fields + signature generation
        - Identifier-based ACL policy override (only sp/st/se)
        - Response override fields NOT decoded (rscc/rscd/rsce/rscl/rsct)
        - Snapshot uses CONTAINER permission table
        - Existing blob Write requirement
        Status: ✅ COMPLETE

   7.13 BlobTokenAuthenticator (194 lines)
        - Implements IAuthenticator
        - Bearer prefix extraction
        - HTTPS requirement
        - JWT decode WITHOUT signature verification
        - Required claims: nbf, exp, iat
        - Time validation uses context.startTime
        - OAuth level dispatch (BASIC only)
        Status: ✅ COMPLETE

   7.14 PublicAccessAuthenticator (125 lines)
        - Implements IAuthenticator
        - Requires container name
        - Metadata error swallowing
        - Two allowlists: CONTAINER_PUBLIC_READ_OPERATIONS, BLOB_PUBLIC_READ_OPERATIONS
        - Returns None for known access type but non-allowlisted operation
        Status: ✅ COMPLETE

HIGH CONFIDENCE (Must Test Explicitly) — 8 Issues:
   1. BlobStorageContext setter mutation via interior mutability
      - Risk: Clone behavior unclear (shared state vs independent)
      - Test: Set on one clone, verify other clones affected/unaffected
      - TS Parity: ✅ TS behavior same (direct mutation)

   2. StorageError timestamp precision
      - Risk: RFC3339 millis format (3 decimals) vs microseconds or other
      - Test: Parse XML body, verify timestamp format
      - TS Parity: ✅ TS uses toISOString() (millis, always Z)

   3. BlobSharedKeyAuthenticator whitespace handling
      - Risk: Implementation comment says "normalize" but code doesn't
      - Test: Header with internal whitespace, verify signature matches
      - TS Parity: ✅ TS also doesn't normalize (implementation correct)

   4. BlobSASAuthenticator field decoding asymmetry
      - Risk: rscc/rscd/rsce/rscl/rsct NOT decoded (unlike other fields)
      - Test: Verify these fields NOT decoded, others are
      - TS Parity: ✅ TS has same asymmetry

   5. BlobTokenAuthenticator Bearer extraction
      - Risk: Offset calculation ("Bearer " = 7 chars, +1 for space = 8)
      - Test: Extract "Bearer TOKEN" → verify "TOKEN" without "Bearer "
      - TS Parity: ✅ TS uses substr(prefix.length + 1)

   6. AccountSASAuthenticator IP validation stub
      - Risk: Always returns true (intentional per TS TODO)
      - Test: Verify method called but result ignored
      - TS Parity: ✅ TS has same stub with TODO comment

   7. OperationBlobSASPermission empty string handling
      - Risk: Empty permission string should always fail validation
      - Test: Verify new("").validate(...) always returns false
      - TS Parity: ✅ TS has same behavior

   8. Error factory message snapshots
      - Risk: 74 factory methods, each with specific message/code/status
      - Test: Snapshot all error outputs, compare byte-for-byte
      - TS Parity: ✅ Exact match required for all

MEDIUM CONFIDENCE (Edge Cases) — 6 Issues:
   9. SAS version string comparison (lexicographic)
      - Risk: Non-standard versions ("2020-01-01") may not sort as expected
      - Test: Edge case versions, verify fallback to correct layout
      - TS Parity: ✅ TS uses >= string comparison

   10. Secondary endpoint "-secondary" suffix
       - Risk: Off-by-one in account name detection within path
       - Test: Path=/account-secondary/container/blob, verify secondary handling
       - TS Parity: ✅ TS checks indexOf(account) === 1

   11. StorageError extra fields XML order
       - Risk: BTreeMap (lexicographic) vs TS (insertion order)
       - Test: Multiple extra fields, verify XML element order
       - TS Parity: ⚠️ May differ (BTreeMap is deterministic)

   12. ContainerSASPermissions.Any identification
       - Risk: Sentinel "AnyPermission" should NOT be permission character
       - Test: Verify Any is special-cased, not treated as "A"
       - TS Parity: ✅ TS has same sentinel behavior

   13. BlobSASAuthenticator policy override scope
       - Risk: Only sp/st/se override from ACL (not protocol/IP/ses)
       - Test: Fetch policy, verify selective override
       - TS Parity: ✅ TS overrides only these three

   14. Error message text exact matching
       - Risk: 74 factory methods + auth error messages must match exactly
       - Test: String comparison for all error messages
       - TS Parity: ✅ Source of truth is TS implementation

TYPESCRIPT PARITY REQUIREMENTS (30+ Behaviors)
================================================================================

StorageError (5):
   • XML special char escaping (<>&"')
   • Message format: {msg}\nRequestId:{id}\nTime:{iso} (newlines + RFC3339 UTC)
   • Headers always: x-ms-error-code, x-ms-request-id
   • Extra fields as XML siblings
   • Content-Type: application/xml

StorageErrorFactory (7):
   • 74 distinct factory methods
   • Context ID defaults: mix of DEFAULT_ID and empty string
   • MD5 fields: both UserSpecifiedMd5 + ServerCalculatedMd5 in XML
   • Page range header injected post-construction
   • 3 snapshot error variants (different codes/messages)
   • Tag error quirk: "DuplicateTagNames" (not "InvalidTag")
   • Query parameter conditional extra fields

Permission Validation (4):
   • ANY-character matching (not ALL)
   • Sentinel handling (Any/AnyPermission = has content)
   • Two permission tables: blob-level vs container-level
   • Snapshot routes to CONTAINER table

Signature Generation (8):
   • 4 SAS versions (2015/2018/2020/2015)
   • 4 UDK versions (2018/2020-02/2020-12/2025)
   • Canonical names: /blob/{account}/{container}[/{blob}] (no URL encoding)
   • String-to-sign: version-specific field arrays joined by \n
   • Empty fields preserved in signature
   • Blob vs BlobSnapshot different handling in UDK paths

Shared Key (6):
   • String-to-sign: method\n + headers + \n + x-ms-headers + \n + resource
   • Content-Length: 0 → "" (not "0")
   • Query keys lowercase, values decoded
   • Secondary endpoint: "-secondary" after account name
   • Key1 and key2 fallback
   • Header whitespace: trim_end name, trim_start value

Account SAS (4):
   • Required: sv, se, sp, ss, srt, sig
   • Strict mode rejects ses
   • Signature first, other validations after
   • Existing blob Write requirement

Blob SAS (6):
   • Resource type: c/b/bs only valid
   • Identifier ACL override: only sp/st/se
   • UDK: 6 signed fields required + signedService="b"
   • Service SAS: both permissions & expiryTime optional if identifier
   • Response override NOT decoded
   • Snapshot uses CONTAINER permissions

JWT Bearer (6):
   • Extract: "Bearer TOKEN" → "TOKEN"
   • HTTPS required
   • Required claims: nbf, exp, iat
   • Signature NOT verified (stub)
   • Time check uses context.startTime
   • Issuer + audience regex + capture matching

Public Access (2):
   • Container name required
   • Metadata errors swallowed
